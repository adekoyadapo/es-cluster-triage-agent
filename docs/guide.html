API Key Setup

You need one key that covers both Kibana deployment and Elasticsearch index access. Paste this in Kibana → Management → Dev Tools. The installer shows the command interactively at startup.

Elasticsearch API Keys Agent Builder permissions

Single installer key — Kibana + Elasticsearch access

POST /_security/api_key
{
  "name": "es-cluster-triage-installer",
  "role_descriptors": {
    "triage-installer": {
      "cluster": ["monitor", "monitor_inference"],
      "indices": [{
        "names": ["<your-monitoring-index>", "<your-log-index>"],
        "privileges": ["read", "view_index_metadata"],
        "allow_restricted_indices": true
      }],
      "applications": [{
        "application": "kibana-.kibana",
        "privileges": [
          "feature_agentBuilder.all",
          "feature_actions.read",
          "workflowsManagement:read"
        ],
        "resources": ["space:default"]
      }]
    }
  }
}

Replace the placeholders with your values:

Monitoring index .monitoring-es-8-mb  or  .monitoring-es-*  or  metrics-elasticsearch.*
Logs / audit index filebeat-9.3.4  or  logs-elasticsearch.*  or  elastic-cloud-logs-8
Space resource "space:default" for the default space, or "space:<your-namespace>" for a custom space (e.g. space:cluster-triage)

Why feature_agentBuilder.all instead of all?
Kibana feature privileges for API keys must use the specific feature name format (feature_agentBuilder.all), not the generic "all" shorthand. Using "all" alone does not grant Agent Builder access to an API key — it only works for user roles assigned through the Kibana UI. feature_actions.read is also required if the agent uses AI connectors.

Why monitor_inference?
The Agent Builder uses the Elasticsearch Inference API for AI-powered query generation and ES|QL generation. Without this cluster privilege the agent chat and tool execution will fail.

Why allow_restricted_indices: true?
Monitoring indices like .monitoring-es-* are restricted system indices in Elasticsearch 8.x. Omit this flag if you're using metrics-elasticsearch.* or other non-restricted patterns.

If aliases can't be created (403 on indices:admin/aliases), the installer falls back automatically — tool queries are patched to use your index patterns directly, so deployment still succeeds without manage privilege.

💡 Simplest option: Use the elastic superuser with its password — the installer accepts username/password in addition to API keys. No role-descriptor tuning needed.

Installation Walkthrough

Run python3 install/install.py and follow the prompts.

Prerequisite Check
Verifies Python 3.8+, confirms the bundle files are in place (19 tools, 5 skills, agent, workflow template).
Agent Builder overview
Connection Details
Prompts for Kibana URL, Elasticsearch URL, and authentication (API key or username/password). Credentials are never echoed to the terminal.
Creating API keys
Auth Validation
Calls /api/status on Kibana and /_cluster/health on Elasticsearch. If either fails, the installer stops with a clear error message — no partial deployments.
API key privileges
Kibana Space
Enter the Kibana space to deploy into (e.g. es-cluster-triage). Lists available spaces. Creates the space if it doesn't exist.
Kibana Spaces
Datastream Configuration
Enter your monitoring datastream pattern (default: .monitoring-es-*) and your log/audit pattern (default: same as monitoring). The installer resolves matching indices, then creates two aliases automatically:
  • es-monitoring → your monitoring indices (including Kibana monitoring sibling if found)
  • elastic-cloud-logs-8 → your log indices (only when pattern differs from default)
All tool queries are rewritten to use these aliases at deploy time.
Stack Monitoring setup ES|QL reference
Deployment
Deploys in order: tools → skills → agent → workflow. Optionally adds a Slack connector post-install. Shows a live progress bar. Saves an install manifest to install/.installed.json.
Agent Builder Kibana Workflows
Verification
Confirms each component is reachable in Kibana. Reports missing items with specific guidance.
Agent Builder API
Summary
Shows a clean summary with the Kibana URL, what was deployed, and next steps. Optionally builds the MCP desktop app.

Automated Workflow

The Kibana Workflow runs on alert triggers or a schedule, producing automated AI triage reports.

Kibana Workflows Create alert rules
TRIGGER
Kibana Alert
Any Kibana rule — Elasticsearch health, ML anomaly, custom threshold
→
STEP 1
ES|QL Metrics
Queries cluster metrics from monitoring index — heap, CPU, rejections, node count
→
STEP 2
AI Agent
Triage agent interprets evidence, uses tools as needed, returns a Markdown report

Alert Report Format

**Summary**        One-sentence overall finding
**Most likely issue** Root cause hypothesis
**Evidence**       Key numbers from the tool results
**Impacted scope** Cluster / node / index name
**Time window**    Period the evidence covers
**Next checks**    2-3 recommended follow-up actions
**Confidence**     High / Medium / Low with reason

Map alert variables
